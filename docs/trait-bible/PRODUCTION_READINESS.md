# Production handoff and remaining gates

The [Task 015A adversarial review](ADVERSARIAL_REVIEW.md) identifies repetition,
frequency conditioning, accessory restrictions and unresolved joint asset binding.
Its baseline and revised evidence are separate; simulation success does not clear
the artwork-production gates.

## Completed proposal specification

Version 1.0.0 specifies 9 constructor categories, 63 stable selected values, 12
editorial sections, 7 exclusive structural mutation rules, 6 curated singleton
reservation designs, 76 logical source templates and 266 anatomy-family variant
bindings. Every trait has visual intent, metadata values, compatibility, source
requirements, proposed count and explicit unapproved status. Category totals are 5280. Exact and weighted frequency policies are distinguished. No public rarity
classification is introduced.

The existing constructor, PRNG, constraints, logical metadata, fingerprints,
provenance verifier, ingestion and renderer interfaces are unchanged. A separate
proposal adapter maps canonical IDs to `dev-` IDs and hashes textual requirement
descriptors in memory. It cannot approve assets or produce PNGs. Versioned strict
schemas, document generation, targeted tests, simulation auditing and changed-file
boundary enforcement are implemented inside the collection workspace.

The completed deterministic simulation and frequency report are committed as small
review evidence; full logical bundles remain ignored. Reproducible logical output
does not certify visual uniqueness, real image alignment or mint assignment.

## Precise engine and renderer blockers

- The existing engine selects **one definition per category**. It cannot draw hats,
  chains and glasses independently. This proposal uses curated accessory bundles;
  independent multi-accessory selection would need reviewed schema/cardinality
  evolution, not a second collection constructor.
- Structural category replacement accepts a **fixed source set**. It cannot select
  an expression/eyewear/collar source based on both the selected trait and mutation.
  The 266 family bindings are declared, but unresolved for real production.
  A reviewed compiler could expand definitions into explicit compatible variants
  and rebalance shared quotas; it must preserve display values, identity and counts.
  No renderer may silently substitute unbound variants.
- A selected anatomy is replaced for every structural family, preserving the Sheep
  species value. Normal/family expression assets must implement real skeletal
  sockets, quartz refraction and void cutouts. Logical source descriptors cannot
  prove geometry or visual correctness.
- PNG decoding/compositing is absent. The text renderer cannot create production
  images, verify actual alpha/profile/dimensions, execute pixel displacement masks,
  refract materials or measure landmark protection. Choose a reviewed deterministic
  renderer plus pinned codec/runtime and prove pixel-byte reproducibility.
- Current source loading permits **1 MiB per asset and 64 MiB total**. Real 3072px
  lossless sources may exceed these limits. No limit, dependency or safety gate is
  changed here; measure an approved pilot before requesting a scoped change.
- Construction is bounded greedy selection, not a backtracking constraint solver.
  A successful disclosed seed does not prove all seeds or fully dependent exact
  quotas feasible. Never loosen compatibility or attempt bounds to force success.
- Token-ID mapping, reveal assignment/fairness, public commitment chronology,
  metadata storage, publishing authority and rights are still unapproved.

## Resumable collection production architecture

Use immutable job IDs derived from the approved spec, normalized construction
recipe, logical fingerprint, source-manifest/approval hashes and renderer version.
The queue states are PLANNED → SOURCE_READY → RENDERED → QA → OWNER_REVIEW →
APPROVED, with FAILED/QUARANTINED branches. Persist input commitments and checkpoints
before work. Restart only incomplete jobs; never overwrite approved bytes.

Retries must have bounded budgets, recorded reasons and attempt evidence. A changed
source/model/prompt produces a new revision/job, not a silent replacement. Failed
or unapproved outputs stay separate from approved collection assets. Keep original
native masters, derived layers/masks, render files, metadata and audit logs in
distinct namespaces with hash inventories and backups. No queue executes here.

Run technical decoding, alpha/frame/crop checks and logical reconstruction before
visual QA. Compare raw hashes and perceptual similarity to identify potential
duplicates, then manually review borderline cases. Inspect anatomy, primary and
secondary eyes, ear roots, wool coverage, mouth/dentition, clothing intersections,
material continuity, corruption masks, exact backgrounds, lettering, edge artifacts
and 64px/128px readability. Owner review occurs in small checkpointed batches before
scaling. Approval declarations bind exact file bytes and are not authenticated
signatures; protected review authority remains a separate design decision.

Only after source packs and a pilot are approved should a collection rendering
plan request be authorized. Final 5280 image/metadata pairs require independent
counts, hashes, uniqueness and reveal-map verification. No batch generation,
website change, deployment, mint or wallet action is authorized by this handoff.
