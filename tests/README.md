# Test foundation

Root Vitest tests import private workspace source directly. They verify canonical facts, invalid configuration rejection, launch audit requirements, access vocabulary, environment failure behavior, catalog integrity, reproducibility inputs, and structural provenance coverage.

Task 002 adds strict payload/presentation tests for all seven global states, altitude bounds and canonical semantics/order/history, recovery bounds and unknown supply, authority spoof rejection, collector compatibility, commitment version/publication/verification boundaries, development-only partners and public share-card field/reference safety. Server-rendered panels are checked for visible development/ownership labeling and absence of actionable mint/reveal forms. These are behavior assertions, not visual snapshots.

Local browser verification targets `/` and `/development/launch` in a production build, including a 320px viewport, desktop layout, keyboard skip/anchor navigation and reduced-motion behavior. Layout must be measured in the browser, not inferred from string snapshots. No production wallet or chain test is appropriate to these unimplemented boundaries.

Task 002 local evidence: both routes have document scroll width equal to client width at a 320px browser viewport (305px content with the scrollbar). All seven review panels fit without overflowing descendants. At 1440px the review uses two equal columns with no horizontal overflow. Keyboard Tab exposes the skip link with a 2px chartreuse outline; Enter focuses `main`. Keyboard Enter on Recovery navigates to its anchor. All panels show DEVELOPMENT / NOT LIVE and there are zero buttons/forms/inputs/selects. The rendered CSS includes the reduced-motion `scroll-behavior: auto` rule and computed styles show zero animated elements; the browser preference was not emulated (its actual reduced-motion preference was false). No application console errors were observed; unrelated preinstalled browser-extension warnings were present.

Any synthetic art IDs/hashes in validation tests are development-only test data, not collection traits or provenance proof. No test connects to a chain, wallet, RPC, marketplace, or contract. Browser smoke checks are local manual verification in Task 001; automated wallet and mint/reveal end-to-end tests belong to future implemented flows.
